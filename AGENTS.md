# Dr. Claw repository guidance

This repository is the versioned source of truth for the Dr. Claw application, its research workflow, and its skill library. More specific `AGENTS.md` files override this file within their subtrees; in particular, follow `server/AGENTS.md` for backend changes.

## Repository map

- `skills/`: complete skill packages, including their scripts, references, and assets. Never migrate only the `SKILL.md` files.
- `server/templates/AGENTS.md`: research-project guidance generated by Dr. Claw.
- `server/projects.js`: project workspace, skill-link, and compact index generation.
- `agent-harness/`: the optional Python `drclaw` control CLI and OpenClaw bridge. Its canonical agent procedure is `agent-harness/skills/dr-claw/SKILL.md`; shorter harness docs must not override its safety policy.
- `bootstrap/codex/`: the reproducible Codex host bootstrap, manifest, router skill, and doctor.

## Skill-library routing

- Do not expose the entire 170+ skill tree as native Codex skills. Codex recursively scans `.agents/skills`, so a nested `library/` folder still consumes the initial skill-list budget.
- For free-form research or ML work, use the `drclaw-skill-library` router and load only the selected `SKILL.md` plus necessary references.
- Treat filesystem discovery as authoritative for availability. `skills/skills-catalog-v2.json` is a generated UI taxonomy and may not be used as the sole installation inventory.
- Preserve both a skill's frontmatter `name` and its source path. They differ for some imported skills; resolvers must accept the canonical name and the directory alias.
- When changing skill layout, routing, mapping, or the catalog, run the bootstrap router validation and the related server tests. Do not hand-edit generated indexes in research projects.

## Durable constraints

- Keep secrets and machine state out of Git: never add Codex auth/session databases, connector tokens, `.env`, SSH keys, Duo data, API keys, or copied user-home caches.
- On NCSA Delta, use the `ncsa-delta` skill. Login nodes are for editing, lightweight validation, data management, and Slurm submission—not production computation.
- Do not make `approval_policy = "never"` or `sandbox_mode = "danger-full-access"` an unconditional bootstrap default. They belong only to an explicit trusted profile.
- Generated research-project guidance must remain concise, versionable, and compatible with Codex `AGENTS.md` discovery. Mechanical enforcement belongs in tests, hooks, or doctor checks rather than prose duplication.

## Validation

Run the smallest relevant checks first:

```bash
python3 bootstrap/codex/skills/drclaw-skill-library/scripts/query_library.py --validate
python3 -m unittest discover -s bootstrap/codex/tests -v
```

When Node dependencies are available, also run the focused Vitest tests for modified server utilities, followed by `npm test` for broader backend changes.
