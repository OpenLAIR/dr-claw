## 七、已发现并明确拒绝的方案

### 7.1 把 172 个 skills 全部放进 native `.agents/skills`

拒绝原因：Codex 递归扫描，`library/` 子目录也会进入初始 skill list；大集合会消耗上下文预算并截短描述。现方案只 native expose router/Delta，再按需加载。

### 7.2 复制旧机器 `$HOME/.codex`

拒绝原因：会携带 auth、sessions、cache、绝对路径和高权限 config，既不安全也不可移植。

### 7.3 默认复制 `approval_policy=never` 与 `danger-full-access`

拒绝原因：这属于当前机器的高信任状态，只能作为显式 trusted profile，不能成为新服务器默认值。

### 7.4 直接升级 `sqlite3` 到 6.0.1

真实 Delta glibc 为 2.34；`sqlite3@6.0.1` 的 x64 prebuilt 引用了 `GLIBC_2.38`，native load 失败。当前保留 `sqlite3@5.1.7`，并精确升级它的 `tar`、cache、fetch、proxy 安装依赖。5.1.7 的 x64/arm64 binary 在当前支持门槛内可加载。

### 7.5 把 React Router 留在 6.x

测试过 `react-router-dom@6.30.6`，npm audit 仍报告两个 moderate advisory：

- `GHSA-wrjc-x8rr-h8h6`
- `GHSA-337j-9hxr-rhxg`

当前采用 `7.18.2`。现有代码只使用兼容的基础 API，typecheck/build/146 tests 均通过；仍缺独立浏览器级 basename/navigation smoke，见第九节。

### 7.6 为追求完整 npm audit = 0 强升 Electron

临时候选把 Electron 升到 `41.10.3` 后，完整 npm audit 可以到 0，但 `npm run desktop:prepare` 在 Electron native rebuild 时失败：

```text
better-sqlite3 ... PropertyCallbackInfo<v8::Value> has no member named 'This'
node-gyp failed to rebuild better-sqlite3
exit 255
```

原因是新 Electron/V8 与当前 `better-sqlite3` native source 不兼容。该方案已明确拒绝，不能为了 audit 数字破坏桌面构建。

还分别测试过当前 advisory DB 下的 `electron@40.10.3` 和 `40.10.6`：前者仍有新的 direct Electron high，后者仍受 sandbox iframe advisory 影响；只有到 41.10.3 才达到 audit 0，而 41.10.3 正是上述 native rebuild 失败版本。因此不能依据旧 advisory range 假设 40.x 已经为 0，恢复时必须重新查询当日 registry 数据。
